# Humanify Audio Detector — Tester Briefing

Thank you for helping calibrate the AI audio detector. This document explains exactly what you need to do and why it matters.

---

## What you're testing

Humanify is a music platform for human-made music only. We built an audio analyzer that tries to detect whether an uploaded song was generated by an AI tool (Suno, Udio, etc.) or recorded by a real artist.

We need your help collecting test samples to find out how well the detector is actually working — and where it's getting things wrong.

---

## What we need from you

We need **two sets of audio files**, each as MP3 or WAV:

### Set 1 — AI-generated songs (aim for 20+)
Songs you are **certain** were made by an AI tool. Good sources:
- Songs generated on **Suno** (suno.com) — download the MP3
- Songs generated on **Udio** (udio.com) — download the MP3
- Any other AI music generator (Stable Audio, MusicGen, Beatoven, Soundraw, etc.)

**Label each file clearly**, e.g. `suno_pop_song1.mp3`, `udio_hiphop_beat.mp3`

The more variety the better — different genres, moods, tempos.

### Set 2 — Human-recorded songs (aim for 20+)
Songs you are **certain** were performed and recorded by real humans. Good sources:
- Songs from **Bandcamp** by independent artists
- Songs ripped from a CD you own
- Songs from royalty-free libraries where you know they're human (e.g. Free Music Archive, ccMixter)
- Your own recordings or recordings made by friends

**Avoid:** heavily auto-tuned pop, EDM with no live instruments, or anything where you're not sure.

---

## What to do with the files

1. Put AI-generated songs in the folder: `test-samples/ai/`
2. Put human songs in the folder: `test-samples/human/`
3. Run the test harness (details below)
4. Copy the terminal output and send it back to us

---

## Running the test

Make sure the app is running first (or use the Railway URL).

**Against the live Railway app:**
```
npm run test:detector:railway
```

**Against a local dev server (if you have the project running locally):**
```
npm run test:detector
```

The script will upload each file to the analyzer and print a table like this:

---

## What to pay attention to and report back

Please send us the **full terminal output**, plus answers to these questions:

1. **Which AI songs scored low on the "ai" column (below 40)?**
   What generator made them? What genre? Note the file name and score.

2. **Which human songs scored high on the "ai" column (above 60)?**
   What are they? Heavily produced? Electronic? Auto-tuned vocal?

3. **Any songs that caused an error?** (The script will print `FAILED: ...`)
   Tell us the file name and the error message.

4. **Anything that surprised you about the results?**

---

## Important notes

- Files are uploaded to the Humanify analyzer the same way a real user would submit them — nothing is stored permanently
- Max file size is 100 MB; most songs will be well under that
- Analysis takes 5–20 seconds per song depending on length
- The test script runs them one at a time, so a batch of 40 songs will take 5–15 minutes total
- Do not commit audio files to the git repo (the .gitignore blocks this)

---

## Why this matters

Right now we don't know the real false-negative rate (AI songs that slip through) or false-positive rate (human songs that get flagged). Your test data gives us the ground truth we need to:

- Tune the detection thresholds
- Identify which genres fool the detector
- Decide whether the current approach is good enough for production use

Thank you — this is genuinely the most valuable thing you can do to help ship the platform.
